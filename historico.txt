## RESUMEN EJECUTIVO

RunPod Manager es una aplicación Android para gestionar pods de computación GPU/CPU en la plataforma RunPod Cloud. Permite crear, iniciar, detener y eliminar pods, así como conectarse vía SSH con terminal integrado.

---

## 1. PROPÓSITO Y FUNCIONALIDAD PRINCIPAL

La aplicación permite a los usuarios:
- Gestionar pods de computación en la nube (iniciar, detener, eliminar)
- Crear nuevos pods con configuraciones personalizadas de GPU o CPU
- Conectarse a pods vía SSH con terminal interactivo
- Ver detalles del pod: estado, costo, IP, mapeo de puertos
- Configurar API keys y claves SSH
- Ejecutar builds de apps Android y despliegues mediante SSH

## 6. API EXTERNA - RunPod REST API

Base URL: https://rest.runpod.io/v1/

Endpoints (RunpodApi.kt):
- GET    /pods                     Lista todos los pods
- GET    /pods/{podId}            Obtener pod específico
- POST   /pods                    Crear pod
- PATCH  /pods/{podId}            Actualizar pod
- DELETE /pods/{podId}            Eliminar pod
- POST   /pods/{podId}/start      Iniciar pod
- POST   /pods/{podId}/stop       Detener pod
- GET    /networkvolumes          Listar volúmenes de red
- GET    /templates               Listar templates

Autenticación: Bearer token (API Key) vía header Authorization en AuthInterceptor

## 9. DETALLES DE IMPLEMENTACIÓN NOTABLES

### Seguridad y Autenticación

API Key Management (ApiKeyManager.kt):
- DataStore Preferences para acceso reactivo con Flow
- Caché volátil para acceso síncrono en interceptors
- EncryptedSharedPreferences con AES256-GCM para SSH keys

SSH Key Generation (SshKeyManager.kt):
- Genera pares RSA de 4096 bits con BouncyCastle
- Convierte a formatos PEM (PKCS8) y OpenSSH
- Almacenamiento encriptado en SharedPreferences

### Manejo de Errores

Patrón Sealed Result (PodRepository.kt):
sealed class ApiResult<out T> {
    data class Success<T>(val data: T) : ApiResult<T>()
    data class Error(val message: String, val code: Int? = null) : ApiResult<Nothing>()
}

### Implementación SSH

SSHJ Integration (SshManager.kt):
- Config SSH personalizada excluyendo X25519 (compatibilidad Android)
- PromiscuousVerifier para verificación de host (producción necesita verificación real)
- Coroutine scope independiente para reader de output
- SharedFlow con buffer para streaming de output terminal
- Keepalive cada 30 segundos
- Soporte descarga archivos vía SFTP

Terminal Bridge (SshTerminalBridge.kt):
- Crea TerminalSession externa (sin PTY local)
- Puente I/O entre SSHJ y emulador terminal Termux
- Usa Channel para operaciones de escritura ordenadas

Foreground Service (SshForegroundService.kt):
- Mantiene conexión SSH activa en background
- Usa permiso FOREGROUND_SERVICE_DATA_SYNC

### Features del Terminal

TerminalScreen.kt:
- TerminalView de Termux embebido con controlador custom
- Barra de teclas extra con secuencias ANSI (flechas, Ctrl+C, ESC, etc.)
- Barra de proyectos que descubre proyectos Gradle en /workspace/projects
- Entrada por voz con Android SpeechRecognizer (sin diálogo UI)
- Detección instalación app vía PackageManager
- Botones Build/Install/Uninstall (actualmente stubs)
- Redimensionado dinámico de PTY

Procesamiento comandos de voz (TerminalViewModel.kt):
- Convierte a minúsculas, reemplaza doble espacio con tab
- Envía como texto raw sin Enter automático

### Creación de Pods

Startup Script (CreatePodViewModel.kt):
cd /workspace && \
mkdir -p ~/.ssh && echo '<SSH_PUBLIC_KEY>' >> ~/.ssh/authorized_keys && \
chmod 600 ~/.ssh/authorized_keys && \
source /workspace/setup_env.sh && \
/workspace/start_tailscale.sh && \
exec /start.sh

## 14. FUNCIONALIDADES DEL TERMINAL (TerminalScreen + TerminalViewModel)

### 14.1 Barra de Proyectos (ProjectsBar)

La barra superior del terminal permite gestionar proyectos Android remotos:

**Selector de Proyecto:**
- Dropdown que lista proyectos Gradle en `/workspace/projects/` del pod
- Al seleccionar un proyecto, detecta automáticamente:
  - `appPackageName`: Lee del `build.gradle` o `AndroidManifest.xml`
  - `isAppInstalled`: Verifica si la app está instalada en el dispositivo
  - `isApkAvailable`: Verifica si existe APK compilado en el pod

**Botón Build:**
- Ejecuta `/workspace/compilar.sh {proyecto}` vía SSH
- El script en el pod ejecuta `./gradlew assembleDebug --no-daemon`
- Muestra spinner durante la compilación
- Actualiza `buildSuccess` (true/false) según código de salida
- Tras build exitoso, re-verifica si APK existe

**Botón Install:**
- Visible solo si `isApkAvailable == true`
- Descarga APK vía SFTP desde `{proyecto}/app/build/outputs/apk/debug/app-debug.apk`
- Guarda en `context.cacheDir/apks/app-debug.apk`
- Muestra progreso circular con porcentaje durante descarga
- Lanza instalador Android con FileProvider + ACTION_VIEW

**Botón Uninstall:**
- Visible solo si `isAppInstalled == true`
- Abre Settings > App Info (ACTION_APPLICATION_DETAILS_SETTINGS)
- Evita restricciones de ROMs como Oppo/OnePlus que bloquean desinstalación directa

### 14.2 Detección de Instalación/Desinstalación

**BroadcastReceiver (packageReceiver):**
- Escucha eventos del sistema: PACKAGE_ADDED, PACKAGE_REPLACED, PACKAGE_REMOVED
- Actualiza `isAppInstalled` automáticamente cuando el usuario instala/desinstala
- Registrado en init() con RECEIVER_NOT_EXPORTED (Android 13+)
- Desregistrado en onCleared() para evitar memory leaks

### 14.3 Entrada por Voz

- Botón de micrófono en la barra de teclas extra
- Usa Android SpeechRecognizer sin diálogo UI
- Convierte texto a minúsculas
- Reemplaza doble espacio con Tab
- Envía como texto raw al terminal (sin Enter automático)

### 14.4 Barra de Teclas Extra

Teclas especiales para terminal SSH:
- Flechas (↑↓←→) con secuencias ANSI
- Ctrl+C, Ctrl+D, Ctrl+Z
- ESC, Tab, Enter
- Botón de voz

## 15. SCRIPT DE COMPILACIÓN EN EL POD

Archivo: `/workspace/compilar.sh`

```bash
#!/bin/bash
PROJECT_DIR="/workspace/projects/$1"
cd "$PROJECT_DIR"
if [ ! -f "gradlew" ]; then
    echo "Error: gradlew no encontrado"
    exit 1
fi
./gradlew assembleDebug --no-daemon
if [ -f "app/build/outputs/apk/debug/app-debug.apk" ]; then
    echo "Build exitoso"
    exit 0
else
    echo "Error: APK no generado"
    exit 1
fi
```

## 17. FLUJO TÍPICO DE DESARROLLO

1. Usuario conecta SSH al pod desde PodListScreen
2. TerminalScreen carga, descubre proyectos en /workspace/projects/
3. Usuario selecciona proyecto del dropdown
4. Sistema detecta package name y estado de instalación
5. Usuario presiona Build → compila en el pod
6. Si build OK → botón Install aparece
7. Usuario presiona Install → descarga APK + lanza instalador
8. BroadcastReceiver detecta instalación → actualiza UI
9. Botón Uninstall aparece para desinstalar si necesario
